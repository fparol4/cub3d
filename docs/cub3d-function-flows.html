Buffered input and line ownership

parser_read_file → _parser_read_lines → parser_next_line
    → _parser_collect_line → _parser_read_byte / _parser_append_byte

parser_next_line:  1 = allocated line, 0 = EOF, -1 = error
parser_process_line: 1 = accepted, 0 = rejected
internal content status: 2 = accepted map line, ownership retained
  • The reader fetches blocks of 4096 bytes and retries interrupted reads (EINTR). Each line starts at 128-byte capacity and doubles when needed.
  • Newline bytes are consumed; a NUL terminator is added. Embedded NUL input is rejected. A final line without newline is supported.
  • Configuration and blank lines are freed after processing. A stored map line remains owned by the grid. The trimmed inspection copy is always freed.
  • The file is closed even when line processing fails. A close failure also rejects the read.

Configuration: six required fields

NO textures/north.xpm
SO textures/south.xpm
WE textures/west.xpm
EA textures/east.xpm
F 50, 50, 50
C 110, 160, 210
  • A bitmask records NO, SO, WE, EA, F and C. Repeated fields fail; configuration order is flexible before the map.
  • Texture identifiers require space or tab, followed by a nonempty trimmed path. Parsing stores paths; image loading happens later.
  • RGB requires exactly three unsigned decimal values, each 0–255, separated by commas. Extra characters or components fail.
  • Packing: (red << 16) | (green << 8) | blue. Floor 50,50,50 becomes 0x323232.

Map validation: what is actually guaranteed

All six fields
→
At least 3 × 3
→
Legal cells + 1 spawn
→
Check floor neighbors
  • Allowed stored cells: 0, 1, space, and N/S/E/W. Exactly one player marker must exist.
  • Each walkable cell must have four cardinal neighbors that are wall or walkable. Outside the grid reads as space, so exposed floor fails.
  • Every walkable cell is inspected, including rooms unreachable from the player. Disconnected enclosed rooms are accepted.
  • There is no flood fill or reachability requirement in this implementation. README connectivity wording is stale; current tests explicitly accept disconnected regions.

One frame: timing and dirty rendering

game_frame(g)
  if no motion and no redraw: return
  now = common_now()                         error → status=1 → close
  elapsed = 0 on first frame, otherwise now - last_frame_time
  last_frame_time = now; clamp elapsed into [0, 0.05]
  if motion: save player → player_update → compare → mark dirty
  if dirty: screen_clear → screen_render → clear dirty flag

At 2.5 world units/second, a clamped step travels at most 0.125 units before collision. Rotation is 1.8 radians/second. Idle frames avoid redraw work, though the MiniLibX loop still runs.

The timestamp is not updated on the early idle return. The first update after a long idle can use the maximum 0.05-second step. Timing uses gettimeofday, so negative deltas are clamped.

Movement, collision and rotation

forward = forward_key - backward_key
strafe  = left_key - right_key
normalize(forward, strafe)

move_x = (dir_x*forward + dir_y*strafe)
         * 2.5 * elapsed
move_y = (dir_y*forward - dir_x*strafe)
         * 2.5 * elapsed
  • Normalize input so diagonal movement has the same total speed as moving straight.
  • Test four corners at (x ± 0.2, y ± 0.2). Outside bounds or anything other than floor blocks movement.
  • Try the X move first, then Y using the possibly updated X. This allows sliding along a wall.
  • Move before turning. Rotate direction and camera plane by the same 2D matrix; left uses a negative angle and right a positive angle.

Rotation: x′ = x cos(a) − y sin(a), y′ = old_x sin(a) + y cos(a). Saving old_x avoids using an already changed value.

SPEAKER NOTE  Collision is a four-corner square footprint, not an exact circular collision test. Opposite forward/back keys cancel.

→
camera_x in [-1,1]
→

camera_x = 2.0 * i / (300 - 1.0) - 1.0
ray_x = player.dir_x + player.plane_x * camera_x
ray_y = player.dir_y + player.plane_y * camera_x
  • 300 rays cover a 1024-pixel view. Ray i draws pixels from i*width/300 up to (i+1)*width/300, excluding the end.
  • For an east-facing player, left edge ray = (1,-0.6), right edge = (1,0.6). With 300 samples, there is no exact center sample; rays 149 and 150 straddle it.
  • Camera rays are deliberately unnormalized. Their DDA parameter is depth along the unit forward direction, which supplies the projection distance without an extra cosine correction.

DDA: visit grid boundaries in order

_raycast_setup:
  map = floor(player position)
  delta_x = abs(1/ray_x)
  delta_y = abs(1/ray_y)
  step = sign of ray components
  side = time to first X/Y boundary

_raycast_advance:
  choose smaller side time
  record time, add delta, step one cell
  • A zero ray component uses 1e30 as the unreachable boundary distance.
  • Crossing X enters a vertical grid boundary (RAYSIDE_X); crossing Y enters a horizontal boundary (RAYSIDE_Y). Equal times take Y.
  • After each step, reject out-of-bounds access; floor continues, any other cell records a hit.
  • Stop at the first hit or after width + height steps. Hit includes world x/y, side, and the crossing parameter.

The ray moves monotonically through the grid. Choosing the next closest boundary avoids tiny fixed-distance sampling and does not skip a wall cell along the traversed path.

SPEAKER NOTE  Do not confuse delta with distance to the first boundary: delta is the spacing between later boundaries on the same axis.

Math foundations: vectors, cells and units

p = (pos_x, pos_y)       world position
d = (dir_x, dir_y)       unit forward vector
c = (plane_x, plane_y)   camera-plane vector
r = d + u*c             ray direction
q(t) = p + t*r          point on that ray

Depth, Euclidean length, and the fish-eye proof

r = d + u*c; |d|=1; d dot c=0
hit - p = t*r
forward depth D = (hit-p) dot d
                = t * (d dot d + u*c dot d) = t
Euclidean ray length E = |t*r| = t*|r|
cos(theta) = (r dot d)/(|r|*|d|) = 1/|r|
Therefore: E*cos(theta) = t = D

For edge ray r=(1,−0.6), |r|=√1.36≈1.166190. At t=2.5, Euclidean length ≈2.915476 while forward depth is 2.5. Projecting with Euclidean length would shrink this edge wall by factor 1/1.166190≈0.857493.

The stored hit.distance is already t, so no explicit cosine multiplication is needed. Normalizing r without changing the distance calculation would invalidate that shortcut. The proof assumes exact camera invariants; repeated floating-point rotations preserve them approximately.

Bresenham: integer error instead of slope division

dx=|to.x-from.x|; dy=|to.y-from.y|
sx=sign(to.x-from.x); sy=sign(to.y-from.y)
error=dx-dy
Draw current point; stop if at endpoint. Otherwise:
  twice = 2*error                         save once
  if twice > -dy: error -= dy; x += sx
  if twice <  dx: error += dx; y += sy

The ideal segment has a fixed ratio of horizontal to vertical progress. The error accumulator tracks the imbalance in integer units; subtracting dy accounts for an X step, adding dx accounts for a Y step. Both tests can pass in one iteration.

Example from (0,0) to (5,3): dx=5, dy=3, initial error=2. Drawn points are (0,0), (1,1), (2,1), (3,2), (4,2), (5,3). After the first step, error=4; the next iteration steps only X.

The saved twice value must feed both decisions. Endpoint equality is checked before stepping, so a zero-length segment draws once. No dy/dx division is needed, including for vertical lines.
